# Раскраска — веб-версия

Детская раскраска на Nuxt 4 + TypeScript. ТЗ — [docs/TZ.md](docs/TZ.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck
npm run build
```

## Структура

- `app/` — общая часть платформы: вход (`/login`), глобальные стили, плагин «нативности».
- `layers/coloring/` — игра «Раскраска» как отдельный Nuxt-слой: галерея (`/coloring`), экран рисования (`/coloring/[id]`), компоненты, стор инструментов, палитра. Новая мини-игра добавляется ещё одним слоем в `layers/` без правок общей части.
- `shared/utils/` — код, общий для клиента и сервера (список стран, проверка имени).

## Принятые решения

**Экраны и адаптив**

- Мобильные экраны в макете горизонтальные. Экран рисования на телефоне в портретной ориентации показывает подсказку «Поверни телефон» (ширина < 600px). Вход и галерея работают в любой ориентации.
- Экран рисования: до 1024px доска занимает весь экран, на десктопе — не больше 1280×920 по центру со скруглением (как в макете 1320).
- Галерея: не больше 4 колонок (как в макете), на узких экранах колонок меньше, но карточки не уже 140px. Сетка по центру, если помещается; иначе прокручивается внутри экрана.
- Галерея постраничная: 12 карточек на странице — карточка импорта (есть на каждой странице) и 11 артов. При большем количестве внизу появляется пагинация. Номер страницы хранится в адресе (`?page=2`), поэтому переживает обновление страницы. Данные идут через TanStack Query: первая загрузка приходит готовой с сервера (SSR), следующая страница подгружается заранее, при переключении предыдущая остаётся на экране до ответа. Номер вне диапазона сервер заменяет ближайшей существующей страницей.
- Учтены вырезы iPhone (safe area): карандаши справа уходят под вырез, кнопки слева от него отступают.
- Экран входа сделан сами в стилистике макета: страна (список ISO 3166-1, страна по умолчанию — по языку браузера) и имя.
- Страна выбирается в своём выпадающем списке, а не в `<select>`: нативный не показывает картинки и не ограничивает высоту, а эмодзи-флагов нет в Windows. Флаги — SVG из пакета `flag-icons`, раздаются как статика `/flags/<код>.svg` и грузятся лениво при прокрутке (все вместе ~1.9 МБ). Есть поиск и управление с клавиатуры. Меню открывается вниз или вверх — где больше места, а на низком экране (телефон горизонтально) — на всю высоту поверх формы.

**Панели инструментов и цветов**

- В макете 8 карандашей отдельными картинками; для 32 цветов используется один рисунок карандаша с подменой цвета. Активный предмет выдвинут на 30px — так в макете отличаются ширины 90 и 60.
- Выбранный инструмент переезжает наверх, остальные анимированно перестраиваются.
- Под активным цветом видны два недавних. Нажатие на активный карандаш открывает палитру: инструменты уезжают, карандаши выезжают по очереди снизу вверх, список прокручивается. Выбор цвета закрывает палитру; закрыть её можно и касанием рисунка или клавишей Esc.
- Если выбрана резинка, выбор цвета возвращает последний рисующий инструмент.
- 8 цветов взяты из макета, остальные 24 подобраны сами.

**Прогресс**

- Рамка — «дорожка» (`#CDF4FF`), заполнение рисуется поверх неё более насыщенным голубым (`#36A9E8`, в макете только 0%) от 180° против часовой стрелки.
- Процент «0%» прижат к правому краю: в макете у «0%» зафиксирован левый край, и «100%» уехало бы за рамку.

**«Нативность»**

- Нет скролла страницы, pull-to-refresh, выделения текста, зума (щипок, двойной тап), перетаскивания картинок и меню по долгому тапу.

## Пока заглушки

- Арты отдаёт API `/api/coloring/arts` (список с пагинацией) и `/api/coloring/arts/[id]`, но пока из заглушки без базы: три базовых арта (осьминог, кошка, дом) в PNG и без прогресса.
- Вход без сервера: после проверки формы сразу открывается галерея.
- Импорт SVG, рисование, история, сохранение и шеринг — следующие этапы.
