# Раскраска — веб-версия

Детская раскраска на Nuxt 4 + TypeScript. ТЗ — [docs/TZ.md](docs/TZ.md).

## Запуск

```bash
npm install
cp .env.example .env   # вписать строки подключения к Postgres
npm run db:migrate     # таблицы и базовые арты
npm run dev            # http://localhost:3000
npm run typecheck
npm run build
```

## База данных

- Postgres в Supabase, доступ только с сервера через Drizzle ORM (`postgres.js`). Supabase Auth и `supabase-js` не используются: вход свой (страна + имя).
- Приложение подключается через transaction pooler (порт 6543, `NUXT_DATABASE_URL`, без prepared statements — так требует pooler). Миграции идут через session pooler (порт 5432, `DATABASE_MIGRATION_URL`).
- Строка подключения задаётся только при запуске (`runtimeConfig`) и в сборку не попадает.
- На всех таблицах включён RLS без политик: REST API Supabase с публичным ключом к ним доступа не имеет, сервер подключается ролью `postgres` и RLS обходит.
- Схемы лежат рядом с кодом: таблицы игры — в `layers/<игра>/server/db/schema.ts` с префиксом игры (`coloring_arts`). Миграции — `server/db/migrations` (`npm run db:generate` после изменения схемы, `npm run db:migrate` для применения).
- Деплой: в Vercel задать `NUXT_DATABASE_URL`, регион функций — `dub1` (база в eu-west-1, Ирландия). Миграции применяются вручную перед деплоем.

## Структура

- `app/` — общая часть платформы: вход (`/login`), глобальные стили, плагин «нативности».
- `layers/coloring/` — игра «Раскраска» как отдельный Nuxt-слой: галерея (`/coloring`), экран рисования (`/coloring/[id]`), компоненты, стор инструментов, палитра. Новая мини-игра добавляется ещё одним слоем в `layers/` без правок общей части.
- `shared/utils/` — код, общий для клиента и сервера (список стран, проверка имени).

## Принятые решения

**Экраны и адаптив**

- **Отступление от макета: на телефоне игра только вертикальная.** Мобильные фреймы в макете горизонтальные (844×390), но на телефоне с панелью браузера горизонтальный экран получается слишком низким. К тому же игроку с выключенным автоповоротом приходилось разбираться с ориентацией. Поэтому сделано как в мобильных веб-играх (например, в Яндекс Играх):
  - экран рисования на телефоне вертикально (ширина < 600px): сверху дом и камера, посередине холст, внизу полоса — инструменты слева, цвета справа, карандаши остриём вверх. Палитра работает как в ТЗ: инструменты уезжают вниз, цветные карандаши по очереди выезжают на их место, полоса листается вбок;
  - телефон горизонтально (сенсорный экран ниже 500px) — экран закрыт подсказкой «Поверни телефон» на всех страницах. Работает на чистом CSS, видна сразу, ещё до загрузки скриптов;
  - планшеты и компьютеры — горизонтальная раскладка из макета без изменений (совпадает с Figma до пикселя).
- Полноэкранный режим на телефонах (Android) в галерее и на экране рисования. Прячет панель браузера и системные кнопки и фиксирует вертикальную ориентацию (только на телефонах). Браузер разрешает его только в ответ на нажатие, поэтому он включается по кнопке «Играть» на входе и по нажатию на карточку арта. Если экран открыт по ссылке или после перезагрузки — по первому касанию. Если игрок сам вышел из полноэкранного режима, касания его не возвращают — только следующее явное действие («Играть» или карточка). На iPhone Safari не даёт страницам полноэкранный режим — там работают подсказка и адаптация по размеру (ниже). На компьютере не включается.
- Панель инструментов и цветов подстраивается под свою длину (высоту колонки или ширину полосы): если места мало, карандаши пропорционально уменьшаются, но не мельче 72% (~32px, чтобы попадать пальцем). Если не хватает и этого, показывается меньше недавних цветов. Кнопки отмены и повтора при высоте экрана до 360px — 44px.
- Экран рисования: до 1024px доска занимает весь экран, на десктопе — не больше 1280×920 по центру со скруглением (как в макете 1320).
- Галерея: не больше 4 колонок (как в макете), на узких экранах колонок меньше, но карточки не уже 140px. Сетка по центру, если помещается; иначе прокручивается внутри экрана.
- Галерея постраничная: 12 карточек на странице — карточка импорта (есть на каждой странице) и 11 артов. При большем количестве внизу появляется пагинация. Номер страницы хранится в адресе (`?page=2`), поэтому переживает обновление страницы. Данные идут через TanStack Query: первая загрузка приходит готовой с сервера (SSR), следующая страница подгружается заранее, при переключении предыдущая остаётся на экране до ответа. Номер вне диапазона сервер заменяет ближайшей существующей страницей.
- Учтены вырезы iPhone (safe area): карандаши справа уходят под вырез, кнопки слева от него отступают.
- Экран входа сделан сами в стилистике макета: страна (список ISO 3166-1, страна по умолчанию — по языку браузера) и имя.
- Страна выбирается в своём выпадающем списке, а не в `<select>`: нативный не показывает картинки и не ограничивает высоту, а эмодзи-флагов нет в Windows. Флаги — SVG из пакета `flag-icons`, раздаются как статика `/flags/<код>.svg` и грузятся лениво при прокрутке (все вместе ~1.9 МБ). Есть поиск и управление с клавиатуры. Меню открывается вниз или вверх — где больше места, а на низком экране (телефон горизонтально) — на всю высоту поверх формы.

**Панели инструментов и цветов**

- В макете 8 карандашей отдельными картинками; для 32 цветов используется один рисунок карандаша с подменой цвета. Активный предмет выдвинут на 30px — так в макете отличаются ширины 90 и 60.
- Выбранный инструмент переезжает наверх, остальные анимированно перестраиваются.
- Под активным цветом видны два недавних. Нажатие на активный карандаш открывает палитру: инструменты уезжают, карандаши выезжают по очереди снизу вверх, список прокручивается. Выбор цвета закрывает палитру; закрыть её можно и касанием рисунка или клавишей Esc.
- Если выбрана резинка, выбор цвета возвращает последний рисующий инструмент.
- 8 цветов взяты из макета, остальные 24 подобраны сами.

**Прогресс**

- Рамка — «дорожка» (`#CDF4FF`), заполнение рисуется поверх неё более насыщенным голубым (`#36A9E8`, в макете только 0%) от 180° против часовой стрелки.
- Процент «0%» прижат к правому краю: в макете у «0%» зафиксирован левый край, и «100%» уехало бы за рамку.

**Пользователи и вход**

- Вход без пароля, по стране и имени, как в ТЗ. Имя уникально на весь сервис без учёта регистра («Masha» и «masha» — один игрок). Совпали имя и страна — это тот же игрок, он продолжает свою работу. Имени нет — создаётся новый игрок. Имя занято игроком из другой страны — «Это имя уже занято — придумай другое».
- Принятый риск: кто знает имя и страну игрока, тот войдёт под ним. Это следует из требования «без пароля».
- Имя: 3–20 символов, буквы любого алфавита, цифры и `_ . -`. Проверяется одной функцией на клиенте и на сервере (`shared/utils/username.ts`).
- Сессия — случайный токен в httpOnly-cookie (JavaScript страницы её не прочитает) на 180 дней. Срок продлевается, пока игрок заходит. В базе хранится только SHA-256 токена: утечка таблицы не даёт войти под чужой сессией.
- Все страницы, кроме входа, и все `/api/coloring/*` требуют сессию. Страницы закрывает глобальный middleware, данные — проверка на сервере в каждом обработчике (`requireUser`). Гость, открывший ссылку на арт, после входа возвращается на неё. Если сессия закончилась во время игры, следующий запрос возвращает на вход.
- При смене игрока в той же вкладке кэш запросов очищается — данные разных игроков не смешиваются.

**«Нативность»**

- Нет скролла страницы, pull-to-refresh, выделения текста, зума (щипок, двойной тап), перетаскивания картинок и меню по долгому тапу.

## Пока заглушки

- Арты берутся из базы (`/api/coloring/arts` — список с пагинацией, `/api/coloring/arts/[id]`): три базовых арта (осьминог, кошка, дом) в PNG. Прогресса и своих артов пока нет — они появятся вместе с пользователями.
- Выхода из аккаунта в интерфейсе нет (в макете нет места под него) — только API `POST /api/auth/logout`.
- Импорт SVG, рисование, история, сохранение и шеринг — следующие этапы.
