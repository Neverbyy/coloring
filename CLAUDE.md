## Статус

- Свёрстаны экраны: вход (`app/pages/login.vue`), хаб игр (`app/pages/index.vue`, `/` = `HOME_PATH` — сюда ведёт вход и `safeRedirect` по умолчанию), галерея и экран рисования (слой `layers/coloring/`). Хаб: карточки из `useAppConfig().games` (тип `GameEntry` в `app/types/games.d.ts`: `id`, `title`, `to`, `cover`; платформа объявляет пустой список, каждая игра добавляет себя в `app.config.ts` своего слоя, Nuxt сливает массивы слоёв), пока игра одна — неактивная карточка «Скоро»; на компьютере и планшете — `PAGE_SIZE` 6 и пагинация (`?page=`, общий компонент платформы `Pagination` в `app/components/` с `label`; его же использует галерея), сетка `auto-fit` шириной в 3 колонки (от 1800px — в 6), размер карточки `--card` — `clamp` по высоте и ширине экрана, чтобы 2 ряда + пагинация влезали без прокрутки; все карточки в одном `ul`, чужие страницы скрыты классом `hub__game--other-page` (кроме телефона), смена страницы — `Transition` по ключу страницы, как в галерее; номер страницы вне диапазона — `router.replace` на существующую; на телефоне (`phone-portrait`) список — горизонтальная лента на чистом CSS (`scroll-snap-type: x mandatory`, слайд = 100% ширины, карточка по центру), точки `hub__dots` рендерятся всегда и видны только в `phone-portrait` (без прыжка после гидратации), текущая — по `scrollLeft / clientWidth`; музыка хаба — `/sounds/main-theme.mp3` строкой в `definePageMeta` (та же, что у раскраски, поэтому переход не прерывает музыку). Обложки игр — файлы в `public/games/` и адрес в `cover` (в `app.config.ts` картинку не импортировать: его собирает и Nitro, а он не умеет импортировать PNG); раскраска — `/games/coloring.webp`, сделана из иконки пользователя 1254×1254 PNG 1,5 МБ (оригинал в git не попадал): обрезана по фиолетовой плашке, углы за скруглением плашки залиты средним фиолетовым её краёв (у рамки карточки скругление меньше — иначе в углах были бы белые клинья), 640×640 WebP ~55 КБ, перегонка — через canvas в Chromium. Карточка — как значок приложения: квадратная рамка `frame-card`, обложка во всю рамку (`position: absolute; inset: 0; object-fit: cover`), название под рамкой; обложки игр рисовать во весь квадрат, без полей. Данные галереи — API `layers/coloring/server/api/coloring/arts/` из таблицы `coloring_arts` (три базовых PNG), на клиенте — TanStack Query (`useGalleryQueries.ts`), постранично по 11 артов + карточка импорта; порядок (решение пользователя) — `listGalleryArts` в `galleryArts.ts`: общие арты (админа и базовые) раньше своих, среди общих `published_at desc nulls last` (новый — в начале первой страницы; явный `nulls last`, иначе Postgres ставит `null` первыми), потом `sort_order` (осьминог, кошка, дом), `created_at desc`; свои — от новых к старым. Импорт отвечает `position` (= число видимых общих артов, `countCommonGalleryArts`), галерея открывает страницу `floor(position / GALLERY_PAGE_SIZE) + 1`, в ленте — `showEntry(position + 1)` (+1 — карточка импорта); до 680px вместо пагинации — лента экранов со свайпом и точками (раскладка экранов — `useGalleryScreens`, данные — `useGalleryScreensQuery`, режим — `useMediaQuery`). Вход и сессии работают: таблицы `users`/`sessions` (`server/db/schema.ts`), API `server/api/auth/*`, стор `app/stores/auth.ts`, middleware `app/middleware/auth.global.ts` (страница для гостей — `definePageMeta({ guestOnly: true })`), на сервере `requireUser(event)` в каждом защищённом обработчике. Ответ 401 на клиенте — только через `auth.expire()` (забыть игрока + на вход). Быстрый вход: cookie `quick_login` (path `/`, без `default`, до 4 записей `{ username, country, seenAt }`, новые первыми; **не сужать путь**: Chrome отдаёт в `document.cookie` cookie с путём `/login` только если документ загрузили на `/login` — `pushState` не считается; при входе в SPA с галереи экран входа видел пустой список, Nuxt `useCookie` с `default` сразу записывал `[]`, и список терялся; старое имя `recent_players` с путём `/login` могло остаться в браузерах тестировщиков — потому новое имя) — `useRecentPlayers()` (`remember` ставит `seenAt = Date.now()`), чистые функции и проверка содержимого cookie — `app/utils/recentPlayers.ts` (`parseRecentPlayers`: только записи, прошедшие `isCountryCode` + `validateUsername`, плохой `seenAt` отбрасывается; подпись «вчера / 3 дня назад» — `seenAgo`, по календарным дням); на `login.vue` режимы `form`/`quick`, оба входят через `enter()` → `auth.login` → `remember(auth.user)`. Время обновляется и при выходе: `auth.forget()` (через него идут `logout` и `expire`) кладёт игрока в `previousUser`, `login.vue` в setup делает `remember` и обнуляет его (`useCookie` создаёт наблюдатели, ему нужна область компонента — из стора не вызывать). Список виден только после нажатия «Быстрый вход», в SSR время не рисуется — расхождения часовых поясов сервера и браузера нет. Страница показывает снимок списка (`recentPlayers` — `shallowRef` из `savedPlayers` на момент открытия), а не живую cookie: `remember` при входе срабатывает до перехода в галерею, и без снимка во время «Входим…» появлялась кнопка «Быстрый вход» (первый вход) и прыгал порядок строк; снимок обновляется только после «×» и неудачного входа (`stopEntering`). Проверка «телефон или мышь» — `isTouchDevice()` (`app/utils/device.ts`). Рисование работает (см. «Движок рисования» ниже). Импорт своего SVG работает (см. «Импорт SVG» ниже). Админка и статистика работают (см. «Админка» ниже).

## Стек и структура

Проверка: `npm run typecheck` (серверные файлы — `npx vue-tsc --noEmit -p .nuxt/tsconfig.server.json`: `nuxt typecheck` их не проверяет). Автотесты — Vitest (`npm test` = `scripts/test.ts`: запускает Vitest из `realpathSync.native` пути — с рабочей папкой `c:\…` (маленькая буква диска, так открывает терминал VS Code и эта среда) Vitest грузит себя дважды и все файлы падают с «failed to find the runner»; `npx vitest` напрямую — только из `C:\…`; папка `tests/`, без базы и браузера: ``, `localStorage`, таймеры подменяются): импорт SVG, проверка истории, разметка, автосохранение, доступ к админке, имя игрока, масштаб холста, список быстрого входа. В Vitest есть алиасы `~`, `#shared`, `#layers/coloring`; автоимпортов нет — файлы, которые тестируются, импортируют зависимости явно. Новую рискованную логику покрывать там же; устанавливать пакеты с `--ignore-scripts`, пока работает dev-сервер пользователя (`postinstall` = `nuxt prepare` пишет в `.nuxt`).
- Vite — сборщик Nuxt по умолчанию; настройки в `vite` в `nuxt.config.ts` (`optimizeDeps.include: ['@tanstack/vue-query', '@supabase/realtime-js']`). Версии новых пакетов — точные и не свежее ~2 недель (`--save-exact`).
- Платформа — `app/`, игра «Раскраска» — Nuxt-слой `layers/coloring/` (автоподключение из `layers/`), общий код клиента и сервера — `shared/utils/`. Новый слой подхватывается только после перезапуска dev-сервера.

Глобальные стили — `app/assets/styles/main.scss`. Индикатор загрузки — `LoadingSpinner` (`app/components/`; `delayed` — проявляется через 150 мс, чтобы не мигать при быстрой загрузке). В миниатюре (`ColoringThumbnail`) он есть уже в SSR и лежит под картинкой; у контура (`thumbnail__image`) белый фон и высота `auto` — до загрузки у картинки нулевая высота, после загрузки она закрывает спиннер даже с прозрачным фоном и ещё до гидратации (не задавать ей высоту и `object-fit`).

## Решения (предварительные, до звонка)

- **Деплой и БД:** Vercel + Supabase Postgres (проект в eu-west-1 → регион функций Vercel `dub1`). Переменные окружения задаются в Vercel, после изменения — Redeploy.
- **Доступ к БД:** только сервер, Drizzle ORM + `postgres.js` (`server/utils/db.ts`, `useDb()`); Supabase Auth/`supabase-js` не используем. Приложение — transaction pooler 6543 (`NUXT_DATABASE_URL` → `runtimeConfig.databaseUrl`, `prepare: false`; **конвейер postgres.js выключен** — `max_pipeline: 0`, у транзакций свой пул с `max_pipeline: 1` (`db.transaction` подменён): с конвейером пулер путал ответы между запросами и терял их — запросы висли; не возвращать), миграции — session pooler 5432 (`DATABASE_MIGRATION_URL`). Схемы — `layers/*/server/db/schema.ts`, таблицы с префиксом игры; миграции — `server/db/migrations` (`npm run db:generate` / `db:migrate`). **На каждой новой таблице — `.enableRLS()`** без политик, иначе она открыта через REST API Supabase по публичному ключу.
- **Архитектура под мини-игры:** общий «слой платформы» (вход, сессия, галерея, аналитика, админка) + игра «раскраска» отдельным модулем (Nuxt Layers или `games/coloring`). Новая игра подключается без правок общей части.
- **Движок рисования** (`layers/coloring/app/engine/`, чистый TS без Vue): `segmentation.ts` — сегменты по растру картинки (линии = тёмные пиксели, фон = касается края, в процент не входит; разрывы линий до 2 × `GAP_CLOSE` закрываются ростом «ядер» — при `GAP_CLOSE` 3 базовые арты размечаются как без него, больше — режет узкие проходы; горячие циклы без замыканий и вызовов на пиксель, иначе V8 не встраивает и разметка дорожает вдвое); `engine.ts` — холсты paint/preview, штрих обрезается маской сегмента (на служебном холсте `stroke` он рисуется только в рамке сегмента — после штриха чистится только она, иначе след попадал в соседний сегмент чужим цветом), заливка/очистка, повтор операций, процент; резинка, которая ничего не стёрла, — не действие: перед штрихом сегмент копируется на служебный холст `backup`, на `endStroke` альфа в рамке штриха сравнивается через `probe` (`willReadFrequently`), пустой штрих → `null`; очистка удержанием пустого сегмента пропускается (`hasPaint`); `cancelStroke` резинки возвращает стёртое из `backup`; `textures.ts` — толщины инструментов и фактура карандаша «блёстки» (плитка белых/чёрных крупинок поверх цвета через `source-atop`, привязана к бумаге). Толщина и прозрачность кисти/карандаша — диапазоны `STROKE_WIDTH_RANGES` (кисть 8–80, карандаш 3–30, `initial` 34/12 — как раньше) и `STROKE_OPACITY_RANGE` (0.1–1; ниже 0.1 альфа меньше `PAINTED_ALPHA` 24 и краска не засчиталась бы в процент) в `shared/history.ts`, в операции `StrokeOp.w`/`a`, `FillOp.a` (без полей — значения по умолчанию, старая история); сервер проверяет `parseStrokeWidth` (целое в диапазоне) и `parseStrokeOpacity` (в диапазоне, кратно 0.01 с допуском на погрешность дробей, округляется). Краска накапливается (решение пользователя: «как изначально», «замещение» убрано): штрих рисуется непрозрачным на служебном `stroke` и в `flush` переносится на предпросмотр с `globalAlpha = a`, маска и фактура — уже без альфы (иначе альфа применилась бы дважды); на `endStroke` предпросмотр ложится на краску поверх — внутри одного штриха цвет ровный, каждый новый штрих по тому же месту темнее; заливка тоже ложится поверх, без очистки сегмента. Пустой штрих резинки (допуск `CHANGE_TOLERANCE`) отменяется с восстановлением из `backup`; заливка хранит `tool` (`FillOp.tool`, без него — кисть, старая история). Выбор — стор `coloringTools` (`widths`/`opacities` — сами значения, у кисти и карандаша свои; `setWidth`/`setOpacity` ограничивают диапазоном и округляют; `strokeWidth`/`strokeOpacity`, `optionsOpen`): повторное нажатие на выбранную кисть/карандаш открывает `ColoringStrokeOptions` в `.board__right` экрана рисования (не внутри `SidePanel` — там `overflow: hidden`) — два `input type=range` (толщина; «прозрачность» = 1 − непрозрачность, 0–90% шаг 5, вправо прозрачнее) и кружок-превью, `data-silent` (без щелчка на каждое отпускание), `closePalette` закрывает и её; на ручке активного инструмента — точка `side-panel__badge` (6–14px по доле толщины в диапазоне); `history.ts` — журнал + снимки каждые `SNAPSHOT_INTERVAL` (20) операций, undo = снимок + доигрывание; `sync.ts` — автосохранение на сервер с повторами и «хвостом» в localStorage. Движок, история и автосохранение связаны в `DrawingSession` (`engine/session.ts`): все действия игрока — через `commit`/`undo`/`redo`. Vue-обёртка — `components/coloring/Canvas.vue` (только ввод: касания, удержание 0.45 с = заливка; картинки в простое). Кнопка холста одна — «Очистить рисунок», компонент `ColoringCanvasControls`, стоит в двух местах страницы `pages/coloring/[id].vue`: над холстом (`.frame__controls` в `.frame__top`) и в верхней строке телефона слева от камеры (`.board__controls`, только `phone-portrait`); показ переключают обёртки страницы, не класс на корне компонента; сброс — операция `{ t: 'reset' }` (`engine.apply` → `reset()`; пустой холст — не действие, `hasAnyPaint`). Масштаб без кнопок и режимов (решение работодателя; лупы и кнопку «Масштаб» убрали): колесо — `onWheel` в `Canvas.vue` (`@wheel.prevent` всегда — иначе Ctrl+колесо/щипок тачпада масштабирует страницу), плавно в точку курсора своей анимацией (`addWheelZoom` копит оставшийся масштаб в логарифме, сразу ограниченный 1–3×, чтобы не копился «долг» за краем; `stepWheelZoom` каждый кадр доводит его долю вокруг точки под курсором через `pinchView`, `WHEEL_SMOOTH_MS` 50; `wheelDelta` приводит строки/страницы к пикселям и усиливает щипок тачпада `ctrlKey`); **у `.art-canvas__view` нет CSS-`transition`, есть `will-change: transform`** — переход, перезапускаемый каждым событием колеса, давал мигание белым и сдвиг краски относительно контура (слои холстов и контур с `mix-blend-mode: multiply` перестраивались вразнобой); в headless-записи это не воспроизводится, проверять у пользователя; начало штриха и щипка останавливают анимацию (`stopWheelZoom`), во время штриха и щипка колесо не действует (`canvasRect` штриха кэшируется на `pointerdown`); касания — все пальцы `pointerType === 'touch'` в `fingers`, второй палец → `startPinch` (точка между пальцами тянет холст, расстояние — масштаб, `pinchView`), начатый штрих при этом `interruptStroke`: моложе `PINCH_GRACE_MS` (300) — отменяется (`engine.cancelStroke`, без операции), старше — сохраняется (`finishStroke`); после щипка оставшийся палец не рисует (у него нет штриха), пока все не подняты; при смене числа пальцев опора щипка пересчитывается. В Playwright поднять один палец из двух — `Input.dispatchTouchEvent` `touchEnd` с этой точкой (её `id`); точки для касаний в приближённом виде брать от `.art-canvas`, а не от растянутого `.art-canvas__lines` — иначе они уходят за экран. Масштаб — CSS-трансформация обёртки `.art-canvas__view` (`translate(%)` + `scale`), математика — `utils/zoom.ts` (уровни 1–3×, сдвиг не выпускает рисунок из рамки); `toWork()` берёт `getBoundingClientRect()` холста, поэтому координаты бумаги верны при любом масштабе. Служебные холсты — `engine/canvas.ts`, localStorage — только через `utils/storage.ts` (не бросает). Типы и проверка операций — `layers/coloring/shared/history.ts` (общие с сервером). Операции хранят точку, а не номер сегмента. Координаты — на «бумаге» (`paperGeometry` в `shared/history.ts`): картинка + поля, размер зависит только от арта; поля — часть фона, рисовать можно во всей рамке. `.board` на экране рисования ограничен по форме (область рисунка 0.5–1.6), иначе бумага не покроет рамку — при правке раскладки сохранять это ограничение. Ключ localStorage — `pendingStorageKey()` в `engine/sync.ts` (`coloring:v3:…`). **Производительность (лаги при долгом рисовании уже чинили):** с видимого холста краски не читать пиксели (`getImageData`) — Chrome переводит его на процессор; процент — через холст `meter` (`willReadFrequently`). Касания — пачкой раз в кадр (`extendStroke(points[])` из `requestAnimationFrame`), маска — только кусок под областью перерисовки. Картинки (миниатюра, PNG камеры) — в простое. В localStorage — только неотправленный хвост (`coloring:v3:…`), база — отдельным ключом `…:base` один раз. Нагрузочный тест — 150 каракулей, долгие задачи не должны расти. Серверные обработчики рисунка начинаются с `requireDrawingRequest(event)` (`server/utils/drawingRequest.ts`), id арта — `artIdParam`, 404 — `artNotFound()`; тела запросов — `readLimitedBody`/`readImageBody` (картинки отвечают 400, не 413: 413 автосохранение понимает как переполнение истории), отдача — `sendImage` (png/jpeg/svg, `IMMUTABLE_CACHE`) в `server/utils/images.ts`. Изменение строки рисунка — через `withLockedDrawing` (`coloringDrawings.ts`). Тело истории проверяет `parseHistorySave` (`shared/history.ts`).
- **Ориентация (решение пользователя, отступление от макета):** на телефоне игра только вертикальная. Миксины в `_variables.scss`: `@include phone-portrait` — вертикальная раскладка экрана рисования (панели снизу, `SidePanel` переключается CSS-ом в полосу — цвета слева, инструменты справа, выбранные у краёв, карандаши повёрнуты на 90°); `@include phone-landscape` — `app/components/OrientationGuard.vue` закрывает экран «Поверни телефон». - **История на сервере (решение пользователя: не строка на штрих):** одна строка на рисунок — `coloring_drawings` (base_seq + base_image PNG, ops jsonb ≤ ~70, cursor, progress, thumbnail JPEG + thumbnail_updated_at, started_at/completed_at для аналитики). Номера операций сквозные. Отмена — минимум `HISTORY_LIMIT` (50); при 50 + `BAKE_CHUNK` (20) старые операции «запекаются» в базу на невидимом движке (`ColoringEngine.offscreen`). Галерея не выбирает bytea-колонки. Свежие миниатюры вкладки — `useDrawingPreviews` (blob: URL), карточка показывает их раньше серверных. Миниатюра — вся бумага; холст и карточка раскладывают бумагу одной функцией `paperLayout` (utils слоя); миниатюра бумаги — компонент `ColoringThumbnail` (карточка галереи и вкладка игрока в админке). Нет миниатюры у начатого рисунка — `Canvas.vue` создаёт её при открытии арта. Уход из арта — `HistorySync.dispose(lastThumbnail)`: если цикл отправки идёт (`running` — промис цикла), финальные история и миниатюра ждут его, потом по порядку история → миниатюра. **Миниатюру не слать с `keepalive`**: лимит keepalive — 64 КБ на все такие запросы сразу, JPEG 720px с фактурой весит ~100–150 КБ, браузер отклонял запрос (`TypeError: Failed to fetch`), ошибка глоталась, и на сервере оставалась старая миниатюра; история — `keepalive` только если JSON ≤ `KEEPALIVE_MAX_BYTES`. В той же вкладке такой баг не виден (карточка берёт `useDrawingPreviews`), проверять после перезагрузки. Открытие арта: заглушка-миниатюра под холстом до `ready`; `useArtQuery` берёт `initialData` из кэша галереи; состояние и база — `fetchDrawing` (`useGalleryQueries.ts`, TanStack `fetchQuery`), стартует ещё на `pointerdown` по карточке (`ArtCard.vue`), при уходе — `forgetDrawing`. Адреса API арта — `artApiPath(id, path)` и `ARTS_API` в `shared/gallery.ts` (одни для клиента и сервера). Сброс кэша: `invalidateGallery` (импорт, удаление), `invalidateArt` (выход из арта — только его страница). `ProgressFrame` — чистый CSS (cq + calc), с JS-запасным путём по `CSS.supports`; анимируется число `--progress` (зарегистрировано через `@property`), а не `stroke-dasharray` — переход между четырьмя числами dasharray растит куски полосы одновременно из разных мест.

## Как работаем (выводы из прошлого тестового — пейволл в `../paywall`)

- Общение и тексты — **на русском**.
- **Код без комментариев** (решение пользователя, финальный рефакторинг): в код комментарии не добавлять, пояснения решений — в README.md и здесь. Тестовые хуки (`window.__…`) в код не возвращать: проверки Playwright — через интерфейс и пиксели холста.
- **Сначала Figma, потом вёрстка**, совпадение с макетом проверяется измерением. Пиксельную сверку и сценарии Playwright запускать из временной папки вне репозитория (Playwright в проект не добавлять без запроса; Vitest уже есть — по просьбе пользователя).
- **Шрифт:** проверять, какая версия шрифта в Figma, — в прошлый раз Figma использовала Inter 3.19, а Inter 4 давал заметное расхождение.
- **Обводки Figma** с «strokes included in layout» соответствуют CSS `border` (входят в размер), а не `box-shadow: inset`.
- **SSR без «прыжков»:** не прятать/показывать корень дочернего компонента классом родителя — при одинаковой специфичности побеждает порядок `<style>`, который в SSR и после гидратации разный. Оборачивать в собственный элемент страницы.
- Пользователь сам правит код между сообщениями (размеры, отступы) — **уважать его правки**, не откатывать; если правка расходится с макетом, сказать об этом.
- **Не коммитить без просьбы** — пользователь коммитит и пушит сам; деплой на Vercel из git.
- **Секреты:** реальные ключи только в `.env` (в `.gitignore`); `.env.example` — только заглушки (`.env.example` попадает в git). Secret-ключ БД — только на сервере, проверять, что он не попал в клиентский бандл и `.output`.
- **Figma MCP:** у пользователя тариф Starter — лимит вызовов; собирать работу в минимум вызовов `use_figma`. Картинки — через `upload_assets` (POST файла на выданный URL), затем `imageHash` в заливке. В auto-layout Figma нет flex-shrink — высоты «резиновых» блоков задавать как их считает браузер.
- Длинные скрипты для Bash писать в файл (в scratchpad), а не в heredoc — длинный heredoc ломался.
