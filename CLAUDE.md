## Статус

- Свёрстаны экраны: вход (`app/pages/login.vue`), галерея и экран рисования (слой `layers/coloring/`). Данные галереи — API `layers/coloring/server/api/coloring/arts/` из таблицы `coloring_arts` (три базовых PNG), на клиенте — TanStack Query (`useGalleryQueries.ts`), постранично по 11 артов + карточка импорта; до 680px вместо пагинации — лента экранов со свайпом и точками (раскладка экранов — `useGalleryScreens`, данные — `useGalleryScreensQuery`, режим — `useMediaQuery`). Вход и сессии работают: таблицы `users`/`sessions` (`server/db/schema.ts`), API `server/api/auth/*`, стор `app/stores/auth.ts`, middleware `app/middleware/auth.global.ts` (страница для гостей — `definePageMeta({ guestOnly: true })`), на сервере `requireUser(event)` в каждом защищённом обработчике. Ответ 401 на клиенте — только через `auth.expire()` (забыть игрока + на вход). Проверка «телефон или мышь» — `isTouchDevice()` (`app/utils/device.ts`). Рисование работает (см. «Движок рисования» ниже). Импорт своего SVG работает (см. «Импорт SVG» ниже). Аналитики и админки ещё нет.
- Звонок с тех. лидом **не проведён** — 3 рабочих дня отсчитываются после него. Ответы вписываются в `docs/QUESTIONS.md`; после этого обновить раздел «Решения».
- Решения, не заблокированные вопросами, принимаем сами и фиксируем в `README.md` (так требует ТЗ).

## Стек и структура

- Nuxt 4.6 + TypeScript (strict). TypeScript закреплён на `^5` — с TS 7 не работает `vue-tsc`. Проверка: `npm run typecheck`.
- Vite — сборщик Nuxt по умолчанию; настройки в `vite` в `nuxt.config.ts` (`optimizeDeps.include: ['@tanstack/vue-query']`).
- Платформа — `app/`, игра «Раскраска» — Nuxt-слой `layers/coloring/` (автоподключение из `layers/`), общий код клиента и сервера — `shared/utils/`. Новый слой подхватывается только после перезапуска dev-сервера.
- Pinia 4 через `@pinia/nuxt`; сторы в `app/stores/` и `layers/*/app/stores/` (автоимпорт).
- TanStack Query 5 (`@tanstack/vue-query`), плагин `app/plugins/vue-query.ts` с dehydrate/hydrate: запросы с SSR не повторяются в браузере.
- SCSS (`sass`): во все `<style lang="scss">` автоматически подключается `app/assets/styles/_variables.scss` (`$breakpoint-desktop`, миксин `@include desktop`; общие куски оформления — миксины `frame-card`, `frame-focus`, `text-field`, `accent-button`, `pressable`, `on-hover` (только мышь) + `$lift-easing` и `$card-height`, `$color-placeholder` — новые элементы собирать из них). Глобальные стили — `app/assets/styles/main.scss`.
- Node у пользователя 22.18 — Nuxt предупреждает о версии (нужно ≥ 22.22.3), это не ошибка.

## Решения (предварительные, до звонка)

- **Деплой и БД:** Vercel + Supabase Postgres (проект в eu-west-1 → регион функций Vercel `dub1`). Переменные окружения задаются в Vercel, после изменения — Redeploy.
- **Доступ к БД:** только сервер, Drizzle ORM + `postgres.js` (`server/utils/db.ts`, `useDb()`); Supabase Auth/`supabase-js` не используем. Приложение — transaction pooler 6543 (`NUXT_DATABASE_URL` → `runtimeConfig.databaseUrl`, `prepare: false`), миграции — session pooler 5432 (`DATABASE_MIGRATION_URL`). Схемы — `layers/*/server/db/schema.ts`, таблицы с префиксом игры; миграции — `server/db/migrations` (`npm run db:generate` / `db:migrate`). **На каждой новой таблице — `.enableRLS()`** без политик, иначе она открыта через REST API Supabase по публичному ключу.
- **Архитектура под мини-игры:** общий «слой платформы» (вход, сессия, галерея, аналитика, админка) + игра «раскраска» отдельным модулем (Nuxt Layers или `games/coloring`). Новая игра подключается без правок общей части.
- **Движок рисования** (`layers/coloring/app/engine/`, чистый TS без Vue): `segmentation.ts` — сегменты по растру картинки (линии = тёмные пиксели, фон = касается края, в процент не входит; разрывы линий до 2 × `GAP_CLOSE` закрываются ростом «ядер» — при `GAP_CLOSE` 3 базовые арты размечаются как без него, больше — режет узкие проходы; горячие циклы без замыканий и вызовов на пиксель, иначе V8 не встраивает и разметка дорожает вдвое); `engine.ts` — холсты paint/preview, штрих обрезается маской сегмента (на служебном холсте `stroke` он рисуется только в рамке сегмента — после штриха чистится только она, иначе след попадал в соседний сегмент чужим цветом), заливка/очистка, повтор операций, процент; `textures.ts` — толщины инструментов и фактура карандаша «блёстки» (плитка белых/чёрных крупинок поверх цвета через `source-atop`, привязана к бумаге). Кисть и карандаш непрозрачные — повторный штрих не уплотняет цвет, без `globalAlpha`; заливка хранит `tool` (`FillOp.tool`, без него — кисть, старая история); `history.ts` — журнал + снимки каждые `SNAPSHOT_INTERVAL` (20) операций, undo = снимок + доигрывание; `sync.ts` — автосохранение на сервер с повторами и «хвостом» в localStorage. Движок, история и автосохранение связаны в `DrawingSession` (`engine/session.ts`): все действия игрока — через `commit`/`undo`/`redo`. Vue-обёртка — `components/coloring/Canvas.vue` (только ввод: касания, удержание 0.45 с = заливка; картинки в простое). Служебные холсты — `engine/canvas.ts`, localStorage — только через `utils/storage.ts` (не бросает). Типы и проверка операций — `layers/coloring/shared/history.ts` (общие с сервером). Операции хранят точку, а не номер сегмента. Координаты — на «бумаге» (`paperGeometry` в `shared/history.ts`): картинка + поля, размер зависит только от арта; поля — часть фона, рисовать можно во всей рамке. `.board` на экране рисования ограничен по форме (область рисунка 0.5–1.6), иначе бумага не покроет рамку — при правке раскладки сохранять это ограничение. Ключ localStorage — `pendingStorageKey()` в `engine/sync.ts` (`coloring:v3:…`). **Производительность (лаги при долгом рисовании уже чинили):** с видимого холста краски не читать пиксели (`getImageData`) — Chrome переводит его на процессор; процент — через холст `meter` (`willReadFrequently`). Касания — пачкой раз в кадр (`extendStroke(points[])` из `requestAnimationFrame`), маска — только кусок под областью перерисовки. Картинки (миниатюра, PNG камеры) — в простое. В localStorage — только неотправленный хвост (`coloring:v3:…`), база — отдельным ключом `…:base` один раз. Нагрузочный тест — 150 каракулей, долгие задачи не должны расти. Серверные обработчики рисунка начинаются с `requireDrawingRequest(event)` (`server/utils/drawingRequest.ts`), id арта — `artIdParam`, 404 — `artNotFound()`; тела запросов — `readLimitedBody`/`readImageBody` (картинки отвечают 400, не 413: 413 автосохранение понимает как переполнение истории), отдача — `sendImage` (png/jpeg/svg, `IMMUTABLE_CACHE`) в `server/utils/images.ts`. Изменение строки рисунка — через `withLockedDrawing` (`coloringDrawings.ts`). Тело истории проверяет `parseHistorySave` (`shared/history.ts`). В dev `window.__coloring` = { engine, history, map, segment } (segment — повторная разметка для замера) — для проверок Playwright.
- **Ориентация (решение пользователя, отступление от макета):** на телефоне игра только вертикальная. Миксины в `_variables.scss`: `@include phone-portrait` — вертикальная раскладка экрана рисования (панели снизу, `SidePanel` переключается CSS-ом в полосу, карандаши повёрнуты на 90°); `@include phone-landscape` — `app/components/OrientationGuard.vue` закрывает экран «Поверни телефон». Планшеты и компьютеры — горизонтальная раскладка из Figma, её не ломать (сверять с макетом). Полноэкранный режим (Fullscreen API) пробовали и убрали по решению пользователя — панель браузера в вертикали не критична; не возвращать без запроса.
- **История на сервере (решение пользователя: не строка на штрих):** одна строка на рисунок — `coloring_drawings` (base_seq + base_image PNG, ops jsonb ≤ ~70, cursor, progress, thumbnail JPEG + thumbnail_updated_at, started_at/completed_at для аналитики). Номера операций сквозные. Отмена — минимум `HISTORY_LIMIT` (50); при 50 + `BAKE_CHUNK` (20) старые операции «запекаются» в базу на невидимом движке (`ColoringEngine.offscreen`). API: `GET state`, `POST history` («заменить операции после fromSeq», идемпотентно; 409/413 → клиент выравнивается или шлёт базу), `PUT base/[seq]`, `GET base`, `PUT/GET thumbnail`. Галерея не выбирает bytea-колонки. Свежие миниатюры вкладки — `useDrawingPreviews` (blob: URL), карточка показывает их раньше серверных. Миниатюра — вся бумага; холст и карточка раскладывают бумагу одной функцией `paperLayout` (utils слоя). Нет миниатюры у начатого рисунка — `Canvas.vue` создаёт её при открытии арта. Открытие арта: заглушка-миниатюра под холстом до `ready`; `useArtQuery` берёт `initialData` из кэша галереи; состояние и база — `fetchDrawing` (`useGalleryQueries.ts`, TanStack `fetchQuery`), стартует ещё на `pointerdown` по карточке (`ArtCard.vue`), при уходе — `forgetDrawing`. Адреса API арта — `artApiPath(id, path)` и `ARTS_API` в `shared/gallery.ts` (одни для клиента и сервера). Сброс кэша: `invalidateGallery` (импорт, удаление), `invalidateArt` (выход из арта — только его страница). `ProgressFrame` — чистый CSS (cq + calc), с JS-запасным путём по `CSS.supports`.
- **Админка:** тот же домен, `/admin`, отдельный layout и чанк, `noindex`. Защита — серверная проверка роли для всех `/api/admin/*` (middleware страниц не защищает данные). Вход админа — логин/пароль (учётка из env или БД), сессия в httpOnly-cookie.
- **Сохранение/шеринг (кнопка камеры):** PNG без UI через `canvas.toBlob()` → `navigator.share({ files })` (в системном окне есть «Сохранить изображение»); иначе — скачивание через `<a download>`. PNG готовить заранее (после автосохранения): Safari теряет user activation при долгом `await` перед `share()`. `AbortError` при отмене — не ошибка. Прямое сохранение в галерею без подтверждения в браузере невозможно — описать в README.
- **«Нативность» игры:** без скролла страницы, overscroll/pull-to-refresh, выделения, зума (щипок, двойной тап), перетаскивания картинок и меню по долгому тапу. Готовый рецепт — в соседнем проекте: `../paywall/app/plugins/native-feel.client.ts` и правила `html`/`body`/`img` в `../paywall/app/assets/css/main.css`, viewport `maximum-scale=1, user-scalable=no`. В админке эти ограничения не нужны.
- **Звук:** движок — `app/utils/sound.ts` (эффекты Web Audio: `playSound`, `loopSound`, `preloadSounds`; `AudioContext` только после жеста — `unlockAudio`; тишина по краям записей отрезается сама; музыка — один `<audio>`: `setMusic`, `duckMusic`). Плагин `app/plugins/sound.client.ts`: жест → звук, щелчок по `click` на `button, a[href], [role=button], [role=option], label` (`data-silent` — без щелчка), музыка по `route.meta.music` + `useAudioStore().musicOn` (cookie `music`) + видимость вкладки. Звуки игры — `layers/coloring/shared/sounds.ts`, музыка страниц игры — `pages:extend` в `layers/coloring/nuxt.config.ts`. Звук инструмента — только во время движения штриха (`Canvas.vue`, `strokeMoved`). Кнопка музыки — `app/components/MusicToggle.vue` (в галерее слева сверху; отступ карточек сверху считается от неё). В dev `window.__sound` = { log, context(), music() } — для проверок Playwright.
- **Ошибки API:** русский текст — только в `createError({ message })`; h3 1.x вырезает не-ASCII из `statusMessage`. На клиенте — `errorStatus()` / `errorMessage()` из `app/utils/httpError.ts`.
- **Импорт SVG:** конвертер `layers/coloring/server/utils/svgArt.ts` (`prepareSvgArt`, плагин `svgo`, без БД — его же возьмёт админка). Фигуры → белая заливка + чёрная обводка; тёмная заливка (`INK_LUMA`) — это линия, остаётся чёрной; трассированные SVG (нет обводок, все заливки серые, есть тёмные — `isTraced`) не обводятся, а бинаризуются по яркости (`TRACE_LUMA`); перекраска — после обхода (`recolorShapes`); толщины пересчитываются через масштаб `transform` (не тоньше `MIN_LINE`, у фигур без обводки — `DEFAULT_LINE`, в пикселях растра 1024), маски/обрезки не перекрашиваются, фон фрейма Figma удаляется. Санитизация — белый список элементов и атрибутов; `DOCTYPE` с сущностями — отказ. Ошибки — 422 с русским `message`. Хранение — `coloring_arts.svg` + `owner_id` + `svg_hash` (SHA-256 подготовленного SVG, уникальный индекс с `owner_id`: повтор → 409 через `onConflictDoNothing`) (свои арты видит только владелец; правило видимости — одно, `visibleTo(userId)` в `galleryArts.ts`, его же использует `requireDrawingRequest`; галерея не выбирает колонку `svg`). API: `POST /api/coloring/arts?name=` (тело — файл), `GET [id]/image` (CSP `default-src none`, immutable), `DELETE [id]`. Клиент — `useOwnArts` (импорт и удаление; ошибки — `OwnArtError`; проверка типа/размера с текстами `IMPORT_MESSAGES` из `shared/gallery.ts`, общими с сервером; после сервера — разметка `segmentArt()` из `utils/segmentArt.ts`, общая с `Canvas.vue`: нет областей → DELETE и сообщение), сообщения — `ColoringNotice`.

## Как работаем (выводы из прошлого тестового — пейволл в `../paywall`)

- Общение и тексты — **на русском**.
- **Сначала Figma, потом вёрстка**, совпадение с макетом проверяется измерением. Пиксельную сверку (Playwright + pixelmatch) запускать из временной папки вне репозитория, тестовые зависимости в проект не добавлять без запроса.
- **Шрифт:** проверять, какая версия шрифта в Figma, — в прошлый раз Figma использовала Inter 3.19, а Inter 4 давал заметное расхождение.
- **Обводки Figma** с «strokes included in layout» соответствуют CSS `border` (входят в размер), а не `box-shadow: inset`.
- **SSR без «прыжков»:** не прятать/показывать корень дочернего компонента классом родителя — при одинаковой специфичности побеждает порядок `<style>`, который в SSR и после гидратации разный. Оборачивать в собственный элемент страницы.
- Пользователь сам правит код между сообщениями (размеры, отступы) — **уважать его правки**, не откатывать; если правка расходится с макетом, сказать об этом.
- **Не коммитить без просьбы** — пользователь коммитит и пушит сам; деплой на Vercel из git.
- **Секреты:** реальные ключи только в `.env` (в `.gitignore`); `.env.example` — только заглушки (`.env.example` попадает в git). Secret-ключ БД — только на сервере, проверять, что он не попал в клиентский бандл и `.output`.
- **Figma MCP:** у пользователя тариф Starter — лимит вызовов; собирать работу в минимум вызовов `use_figma`. Картинки — через `upload_assets` (POST файла на выданный URL), затем `imageHash` в заливке. В auto-layout Figma нет flex-shrink — высоты «резиновых» блоков задавать как их считает браузер.
- Длинные скрипты для Bash писать в файл (в scratchpad), а не в heredoc — длинный heredoc ломался.
